# API Gateway Service

A high-performance, non-blocking API Gateway built on **Spring Cloud Gateway (Spring Boot 3.4, Java 17)** integrated with **Keycloak IAM** and **Redis Reactive** for real-time JWT Blacklist validation.

---

## Specific Functions of `api-gateway-service`

1. **Common Entry Point & Cross-Cutting Concerns**:
   - Acts as the single perimeter ingress for all external client traffic (Web, Mobile, Third-party).
   - Offloads cross-cutting requirements—such as centralized TLS termination, CORS policy management, request rate limiting, structured access logging, and routing—so downstream business microservices (e.g., User Service, Order Service) remain purely domain-focused without duplicating infrastructure logic.

2. **Keycloak Token Validation & Signature Verification**:
   - Validates incoming OpenID Connect (OIDC) Bearer tokens generated by Keycloak.
   - Verifies the cryptographic signature against Keycloak's JSON Web Key Set (JWKS) public certificates endpoint (`/protocol/openid-connect/certs`) supporting RS256/ES256 algorithms with in-memory caching and public key rotation.
   - Enforces token freshness by checking expiration (`exp`), not-before (`nbf`), and issuer (`iss`) validity before any internal dispatch.

3. **Real-time JWT Revocation & Redis Blacklist Checking**:
   - Solves the classic stateless JWT revocation limitation (logout, user ban, password change, permission downgrade).
   - Extracts the unique Keycloak token identifier claim (`jti`) from the verified token.
   - Performs non-blocking, asynchronous lookup against Redis Reactive store using `ReactiveStringRedisTemplate` via Lettuce driver in sub-millisecond latency.
   - Rejects revoked or blacklisted tokens immediately with `HTTP 401 Unauthorized` and produces structured warning audit logs containing client IP, User Subject, and Token ID.

4. **Identity & Claims Context Propagation (Header Enrichment)**:
   - Sanitizes and enriches upstream request headers before routing to downstream services.
   - Extracts Keycloak identity claims (Subject `sub`, Preferred Username `preferred_username`, Realm Roles `realm_access.roles`, Email) and injects them as trusted internal headers (`X-Auth-User-Id`, `X-Auth-Username`, `X-Auth-Roles`, `X-Auth-Token-Id`).
   - Enables internal microservices to consume pre-authenticated user context directly without re-parsing or cryptographically verifying JWTs on every internal hop.

5. **Dynamic Route Dispatching & Traffic Control**:
   - Provides predicate-based path routing and URL rewriting to decouple public API contracts from internal microservice topologies.
   - Supports non-disruptive service upgrades, load balancing, canary deployments, and circuit breaking via Resilience4j.

6. **Observable Monitoring & Health Diagnostics**:
   - Exposes Spring Boot Actuator health, readiness, liveness probes, and Prometheus metrics (`/actuator/health`, `/actuator/metrics`).
   - Records granular round-trip latency and HTTP status distribution across all processed gateway requests without thread blockage.

## Architecture Overview

```
 [ Client / Browser / Mobile ]
               │
               ▼  HTTP Request with Bearer <Keycloak JWT>
    ┌────────────────────────────────────────────────────────┐
    │              Spring Cloud Gateway                      │
    │                                                        │
    │  1. Whitelist Check (Excluded Public Paths)            │
    │  2. Keycloak JWKS Signature & Expiry Verification      │
    │  3. Extract Keycloak 'jti' (Token ID)                  │
    │                                                        │
    │  4. Non-blocking Redis Reactive Check:                 │
    │     Key: "jwt:blacklist:<jti>"                         │
    └───────────────────┬────────────────┬───────────────────┘
                        │                │
            Token in Blacklist?     Token Active?
                        │                │
                        ▼                ▼
            ┌──────────────────────┐   ┌────────────────────────┐
            │ HTTP 401             │   │ Enrich Request Headers │
            │ Unauthorized         │   │ X-Auth-User-Id         │
            │ (Log WARN audit)     │   │ X-Auth-Roles           │
            └──────────────────────┘   └───────────┬────────────┘
                                                   │
                                                   ▼ Forward to
                                       ┌────────────────────────┐
                                       │ Downstream Services    │
                                       │ (User / Order Service) │
                                       └────────────────────────┘
```

## Configuration Properties (`application.yml`)

| Property | Default / Example | Description |
|---|---|---|
| `spring.data.redis.host` | `localhost` | Redis server hostname |
| `spring.data.redis.port` | `6379` | Redis server port |
| `jwt.jwk-set-uri` | `http://keycloak:8180/realms/master/protocol/openid-connect/certs` | Keycloak JWKS public key endpoint |
| `jwt.issuer-uri` | `http://keycloak:8180/realms/master` | Expected Keycloak token issuer (`iss`) |
| `jwt.blacklist-prefix` | `jwt:blacklist:` | Key prefix used in Redis for revoked tokens |
| `jwt.excluded-paths` | `/realms/**, /actuator/health, ...` | Paths that bypass token verification |

## Quick Start Guide

### 1. Launch with Docker Compose
Start Keycloak, Redis, Mock Backend, and API Gateway:
```bash
cd api-gateway-service
docker compose up -d
```

- **Keycloak Console**: `http://localhost:8180` (Admin: `admin` / `admin`)
- **API Gateway**: `http://localhost:8080`
- **Redis CLI**: `localhost:6379`

### 2. Revoking a Token (Logout / Ban Flow)
When a user logs out from Keycloak or an administrator revokes a session, add the token's `jti` to Redis with a TTL matching the token's remaining lifespan:
```bash
# Example: Revoke token with JTI "c9c22881-8b2b-4d40-9da2-88749a5ad30a" for 1800 seconds
redis-cli SET "jwt:blacklist:c9c22881-8b2b-4d40-9da2-88749a5ad30a" "REVOKED" EX 1800
```

### 3. Testing with cURL

#### Missing Token (Returns 401):
```bash
curl -i http://localhost:8080/api/v1/users/profile
```

#### Revoked Token (Returns 401 with WARN log):
```bash
curl -i http://localhost:8080/api/v1/users/profile \
  -H "Authorization: Bearer <REVOKED_KEYCLOAK_JWT>"
```

#### Active Token (Returns 200 with enriched headers forwarded):
```bash
curl -i http://localhost:8080/api/v1/users/profile \
  -H "Authorization: Bearer <VALID_KEYCLOAK_JWT>"
```
